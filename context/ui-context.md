## Activity screens

- Shared-data workspace screens (dashboard, task board/detail, notifications, activity, members, project lists, and Trash) refresh when a same-organization/project change arrives. Events invalidate data; clients fetch authoritative data through authenticated REST. Keep reconnect/focus refresh and a visible-screen polling fallback on mobile.

- Admin platform activity follows a compact, card-based layout: page header, search + organization/date controls, range selector, filter chips, and data table/timeline rows.
- The activity view should use a clean purple accent palette for active filter pills and keep controls aligned with the platform admin shell.
- Date filters must never send a future range or a range wider than 366 days. Omit the upper bound for live ranges and custom ranges ending today to avoid client/server clock skew; clamp custom ranges to the supported 366-day window.
- The SuperAdmin activity feed includes platform-scoped registration and authentication events; label their scope as Platform and do not expose them in organization activity feeds.
- Mobile login, registration, and OTP screens should share the web auth brand (TaskFlow), headings, descriptions, purple accent, compact bordered card, and OTP expiry/resend behavior while retaining touch-friendly stacked fields.
- Web auth and workspace/admin sidebars use the mobile app's TaskFlow mark and wordmark from `apps/web/public`, retaining the mark alone in collapsed sidebars; development email preview and favicon use their existing supplied brand assets. The public landing follows `Landing page v2 — Desktop.svg`: use the mobile app's TaskFlow mark and wordmark in the header/footer, the launcher mark in its task-board preview, deep blue and orange accents, and a responsive statement-led hero, four-step workflow, feature grid, AI drafting section, and FAQ.
- The mobile app launcher uses the TaskFlow wordmark as its display name and the symbol/colors from `Mobile launcher.svg` for Android adaptive and legacy icons.
- Unauthenticated mobile entry uses a concise TaskFlow launcher with a short product promise, compact task-board preview, and direct create-account/login actions. Keep the web landing as the longer product-discovery page; the mobile launcher follows its brand and core message without reproducing its full section flow.
- SuperAdmin mobile uses a left-side navigation drawer matching the mobile workspace drawer pattern. The grouped destinations mirror platform administration: Overview and Analytics; Users, Organizations, Projects; Activity, Audit Trail, and System Health; Reports; Platform Settings; and Account & Settings. Keep the compact platform breadcrumb, page search, theme control, and signed-in administrator avatar/footer. The SuperAdmin shell defaults to its own light theme and its theme control must not affect workspace screens. SuperAdmin dates, date filters, greetings, and displayed timestamps use East Africa Time (EAT, UTC+3), independent of the device timezone; do not add an EAT label to the Overview heading. The Overview matches the web dashboard: six KPI cards in a two-column mobile grid, 30-day user/project totals and sparklines, 7/30/90-day project-growth chart selection, task-status donut, five recent projects with organization/task/status/created details, a green pill-style live indicator beside the greeting, and PDF report download. Overview keeps the selected analytics period on refresh. Analytics includes web-matched growth line charts, task-status and priority charts, and period filters. Overview uses the admin dashboard, analytics, and projects endpoints. Activity and Audit Trail use authenticated, paged platform API feeds and pull-to-refresh; Overview, Analytics, Users, Organizations, Projects, Activity, and System Health refresh on their web-equivalent visible-screen intervals. Platform data continues to use authenticated REST rather than workspace SignalR events. Reports provide PDF, XLSX, and CSV selection and save-to-device behavior. Organizations and Projects expose searchable/filterable detail views; Organizations also supports owner filtering and CSV export.
- The Flutter task-creation dialog keeps its form scrollable and sizes the scroll region against the height available above the Android keyboard, since the task-title field receives autofocus.
- Account settings support a profile-picture upload (JPEG, PNG, WebP, or GIF); clients center-crop and resize images to a compressed 512px-square JPEG below the 5 MB API limit. Animated GIFs are flattened to a still image; show the current image with a circular cover crop or initials fallback. Task detail surfaces support file attachments (up to 10 MB) with a move-to-Trash action for the uploader and project managers/leads.
- Web avatar display uses the available profile URL across workspace member lists, team/task workload views, task assignee chips, task comments, signed-in profile menus/sidebars, platform-admin signed-in profile surfaces, and account settings. Preserve initials when no URL exists or the image fails; use square clipped frames and centered circular cover crops. Admin user-management rows and platform activity actors currently lack avatar URLs in their API data and remain initials-only.
- Mobile avatar display uses the existing `AvatarChip` across member lists, project team previews, workload, task assignees, account settings, and signed-in profile surfaces; also show photos in member search and assignee-selection controls. Use circular cover crops with initials fallback when the URL is missing or fails. SuperAdmin user rows and activity actors remain without profile photos because their current API data does not include avatar URLs.
- Workspace Trash lists recoverable projects, tasks, comments, and attachments with their deletion time and restore action; clearly state the 30-day retention. Project Archive remains a separate, indefinite action and must not be presented as deletion.
